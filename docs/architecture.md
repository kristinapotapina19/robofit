# Архитектура и развёртывание

## Назначение и границы решения

РобоФит — веб-платформа экспресс-предынвестиционной оценки роботизации. Пользователь проходит один сценарий: выбор объекта и операции → параметры → подбор решений с объяснением → сравнение → расчёт экономики по трём сценариям → what-if и чувствительность → имитация работы парка на 2D-схеме → сохранение проекта и отчёт PDF/Excel.

**Целевая аудитория:** руководители предприятий и подразделений, технические директора, руководители автоматизации и цифровой трансформации, логисты, финансовые аналитики.

**Границы MVP.** Платформа формирует обоснованную гипотезу и материалы для ТЭО, но не заменяет обследование объекта. Результат явно помечен как предварительная оценка (п. 3.7.5 ТЗ). Нет интеграций с WMS/ERP/1С (описаны ниже как план), нет 3D, нет автоматического парсинга сайтов по расписанию.

## Компоненты

```
┌──────────────┐   /api (JSON)   ┌─────────────────────────────────────────┐   SQL   ┌────────────┐
│  web          │ ─────────────▶ │  api (FastAPI)                           │ ──────▶ │ PostgreSQL │
│  React + Vite │                 │  routes.py        REST, роли, валидация │         │  16        │
│  nginx        │ ◀───────────── │  core/pipeline    сквозной расчёт       │         └────────────┘
└──────────────┘  PDF / XLSX     │  core/operations  профили операций      │  если БД недоступна:
                                 │  core/selection   подбор и рейтинг      │  data/runtime/store.json
                                 │  core/economics   CAPEX/OPEX/TCO/ROI    │
                                 │  core/simulation  имитация смены        │
                                 │  core/params      шаблон, загрузка, проверка
                                 │  core/report      отчёт PDF и Excel     │
                                 │  repo.py          хранилище             │
                                 └─────────────────────────────────────────┘
                                          ▲
              scripts/etl.py  ─────────── │  data/raw → data/seed (каталог, пресеты, отчёт ETL)
```

| Компонент | Технологии | Что делает |
|---|---|---|
| `frontend/` | React 19, Vite 8, без UI-библиотек; canvas для схемы | Пошаговый мастер из 8 шагов, каталог, проекты, администрирование. Имитация в браузере — порт той же модели, что на сервере (`src/sim.js`). |
| `backend/app/api/routes.py` | FastAPI, Pydantic 2 | REST API, роли, проверка параметров, отчёты. OpenAPI: `/docs`, `/openapi.json`. |
| `backend/app/core/` | чистый Python | Расчётное ядро без зависимостей от веба и БД — запускается и тестируется отдельно (`scripts/demo_report.py`). |
| `backend/data/profiles.json` | JSON | Профили операций: объём, режим, персонал, маршрут, ограничения, риски. Новая операция или тип объекта — запись в файле, ядро не меняется. |
| `backend/scripts/etl.py` | pandas, openpyxl | Загрузка каталога и датасетов организатора, обогащение ТТХ, объединение дублей, решения из открытых источников. |
| `backend/app/repo.py` | SQLAlchemy 2 | PostgreSQL в основном режиме. Если БД недоступна при старте — файловое хранилище, чтобы демонстрация не падала (п. 4.2.7, 4.3.4). |

## Модель данных

| Таблица | Ключевые поля | Комментарий |
|---|---|---|
| `solutions` | `external_id`, `data` (JSON), `name`, `subtype`, `price_rub`, `updated_by` | Карточка решения целиком в `data`: идентификация, сценарии, объекты, цена с комментарием, `specs` — каждая ТТХ с `value`, `unit`, `source`, `confirmed`. |
| `users` | `username`, `password_hash`, `role` | PBKDF2-SHA256 с солью; роли `user`, `admin`; гость — без учётной записи. |
| `projects` | `owner`, `title`, `object_type`, `profile_code`, `parameters` | Проекты изолированы по владельцу; администратор видит все. |
| `scenarios` | `project_id`, `solution_external_id`, `parameters`, `overrides`, `options`, `summary`, `catalog_version`, `model_version` | Хранит входы и ключевые результаты. Повторное открытие пересчитывает и сверяет с сохранённым (п. 3.1.5). |
| `settings` | `key`, `value`, `updated_by` | Нормативы по умолчанию, изменённые администратором. |

Справочники объектов (`object_presets.json`) и профили операций (`profiles.json`) — файлы в репозитории: они версионируются вместе с кодом и попадают в `catalog_version`.

## API

Полная спецификация — Swagger на `/docs`. Основные группы:

| Метод | Путь | Доступ | Назначение |
|---|---|---|---|
| GET | `/api/meta` | все | версии, правила подбора, веса рейтинга, интервалы окупаемости |
| POST | `/api/auth/login`, `/api/auth/register` | все | токен для заголовка `Authorization: Bearer …` |
| GET | `/api/catalog/object-types` | все | типы объектов и их операции |
| GET | `/api/catalog/presets/{code}` | все | параметры объекта с демо-значениями, единицами, диапазонами |
| GET | `/api/catalog/solutions` | все | фильтр `object_type, profile, subtype, status`, поиск `q`, сортировка `sort` |
| GET | `/api/catalog/tree` | все | иерархия отрасль → объект → процесс → тип → продукт |
| POST | `/api/params/validate` | все | проверка типов, обязательности, диапазонов |
| GET | `/api/params/template/{object_type}?fmt=xlsx\|csv` | все | шаблон для заполнения |
| POST | `/api/params/upload?object_type=` | все | загрузка Excel/CSV (в т. ч. датасета организатора) |
| POST | `/api/selection` | все | все кандидаты с вердиктом, причинами, вкладом факторов |
| POST | `/api/evaluate` | все | полный расчёт: парк, 3 сценария, трассировка, чувствительность, рекомендация, конфиг имитации |
| POST | `/api/compare` | все | сравнение до 5 решений по единым показателям |
| POST | `/api/report/pdf`, `/api/report/xlsx` | все | отчёт, пересчитанный на сервере |
| GET/POST/PUT/DELETE | `/api/projects…` | user | проекты, копирование, сценарии, воспроизведение расчёта |
| POST/DELETE | `/api/admin/solutions…` | admin | добавление и редактирование решений |
| GET/PUT | `/api/admin/assumptions…` | admin | нормативы по умолчанию |
| POST | `/api/admin/catalog/reload` | admin | перезагрузка каталога после ETL |

Пример расчёта:

```bash
curl -X POST http://localhost:8000/api/evaluate -H 'Content-Type: application/json' -d '{
  "profile_code": "pallet_transport",
  "params": {"Объём приёмки (поддоны/сутки)": 1200},
  "solution_id": "5760e938-9a43-45a7-b8e8-f4f2e6383930",
  "overrides": {"service_share": 0.1},
  "options": {"automation_share": 0.6}
}'
```

Незаполненные параметры берутся из демо-датасета — гость может посчитать сразу.

## Безопасность

- Роли: гость (каталог, подбор, расчёт, отчёт — без сохранения), пользователь (проекты), администратор (каталог, нормативы).
- Пароли — PBKDF2-SHA256, 120 000 итераций, соль на пользователя. Токен — HMAC-подпись, срок 12 ч, секрет `SECRET_KEY`.
- Изоляция: чужой проект возвращает 404 (существование не раскрывается).
- Удаление проекта удаляет сценарии и сохранённые параметры каскадно.
- Демо-данные обезличены (датасет организатора). При размещении в сети — HTTPS на обратном прокси.

## Производительность

Расчёт типового проекта со всеми имитациями — 0,1–1,5 с (требование — до 10 с). Подбор минимального парка стартует рядом с аналитической оценкой, поэтому имитаций 2–5, а не десятки. Каталог и пресеты кешируются в памяти.

## Развёртывание

### Docker Compose (рекомендуется)

```bash
cp .env.example .env
docker compose up --build
```

- интерфейс — http://localhost:5173
- API и Swagger — http://localhost:8000/docs

Контейнеры: `db` (PostgreSQL 16), `api` (FastAPI, при первом старте создаёт таблицы и загружает каталог и демо-учётки), `web` (сборка Vite + nginx, проксирует `/api`).

### Один контейнер для стенда

`Dockerfile` в корне собирает фронтенд и отдаёт его из API. Подходит для любого хостинга с Docker (Render, Railway, Amvera, VPS):

```bash
docker build -t robofit .
docker run -p 8000:8000 robofit                       # файловое хранилище
docker run -p 8000:8000 -e DATABASE_URL=postgresql+psycopg://u:p@host:5432/db robofit
```

Переменные: `DATABASE_URL`, `SECRET_KEY`, `PORT` (по умолчанию 8000).

### Без Docker (разработка)

```bash
cd backend && pip install -r requirements.txt
DATABASE_URL= uvicorn app.main:app --reload      # пустой DATABASE_URL — файловое хранилище
cd frontend && npm install && npm run dev         # http://localhost:5173, /api проксируется на :8000
```

## Интеграции (план)

| Система | Что даёт | Как подключить |
|---|---|---|
| WMS | фактические потоки, маршруты, ячейки — вместо средних значений датасета | импорт выгрузки заданий в `/api/params/upload`, далее — коннектор по API WMS |
| ERP / 1С | ФОТ, численность, ставки, фактические затраты | выгрузка из 1С в шаблон параметров; REST-коннектор к 1С:ERP |
| Мониторинг оборудования | фактическая производительность и простои пилотного парка | сравнение с имитацией, калибровка допущений `utilization`, `availability` |
| Аналитические продукты ФЦ БАС | единый каталог решений и реестры | синхронизация каталога через `/api/admin/solutions` |
| Госреестры и меры поддержки | проверка продукции (реестр российской промышленной продукции), субсидии | поле в карточке решения и отдельная статья в CAPEX |

## Известные ограничения и развитие

1. Производительность большинства решений каталога в единицах конкретной операции не опубликована. Для мобильных роботов она рассчитывается из цикла рейса, для остальных — по типовому значению подтипа; такие значения помечены как требующие подтверждения.
2. Имитация детерминированная (равномерный поток задач в пиковом режиме смены), без столкновений и планировки конкретного здания. Схема условная.
3. Экономия считается по ФОТ целевой операции; дополнительный доход и предотвращённые потери пока не моделируются.
4. Финансирование — за счёт собственных средств; кредит и лизинг — следующий шаг (пояснения к ТЗ, п. 2.1).
5. Каталог обновляется запуском ETL и перезагрузкой из админки; автоматический сбор с сайтов — в плане.

План: калибровка модели по данным пилотов, лизинг и кредит, профили для новых операций (сортировка, инвентаризация), импорт планировки из DXF, роль вендора.
